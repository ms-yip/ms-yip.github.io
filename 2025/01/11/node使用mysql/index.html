一、完整 API 分类及使用场景

1. 连接管理 API

API 适用场景 生产环境建议
createConnection() 简单应用、脚本执行 不推荐生产使用，建议用连接池
createPool() Web 应用、高并发场景 生产推荐，合理设置 connectionLimit
connection.connect() 显式建立连接 通常不需要显式调用，查询会自动连接
connection.end() 优雅关闭单连接 适合脚本程序退出时使用
pool.end() 应用关闭时释放资源 生产必须，在应用退出时调用

2. 查询执行 API

API 适用场景 生产环境建议
.query(sql, callback) 简单查询 最常用，适合大多数场景
.query(sql, [values], callback) 参数化查询 安全推荐，防止 SQL 注入
.execute(sql, [values], callback) 预处理语句 高安全要求场景，性能稍差
.query().stream() 大数据量查询 处理百万级以上数据

3. 事务 API

API 适用场景 生产环境建议
beginTransaction() 开始事务 金融操作、多表一致性要求场景
commit() 提交事务 必须与 beginTransaction 配对使用
rollback() 回滚事务 错误处理中必须实现回滚逻辑

4. 实用工具 API

API 适用场景 生产环境建议
escape() 手动转义值 复杂 SQL 拼接时使用
escapeId() 转义标识符 动态表名/列名时使用
format() SQL 格式化 调试时有用，生产环境少用

MySQL2 npm 包全面解析与生产实践指南

MySQL2 是 mysql npm 包的改进版，提供了更好的性能、更多的特性以及 Promise 支持。以下是完整的 API 解析和生产实践建议。

一、MySQL2 核心优势

  1. 性能提升：比 mysql 快 30-40%
  2. Promise 原生支持：无需手动封装
  3. 预处理语句缓存：提高重复查询性能
  4. 支持命名参数：更直观的查询方式
  5. 更好的类型支持：与 TypeScript 集成更友好
