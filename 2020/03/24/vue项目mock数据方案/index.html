Mock.mock( rurl?, rtype?, template|function( options ) )
Mock.mock( template ) 根据数据模板生成模拟数据。

Mock.mock( rurl, rtype, function( options ) ) 记录用于生成响应数据的函数。当拦截到匹配 rurl 和 rtype 的 Ajax 请求时，函数 function(options) 将被执行，并把执行结果作为响应数据返回。

Strapi 中 Collection Types 和 Single Types 的区别

在 Strapi 内容管理系统中，Collection Types（集合类型）和 Single Types（单一类型）是两种主要的内容结构类型，它们有以下关键区别：

Collection Types (集合类型)

  • 允许创建多个条目：可以创建多个相同结构的内容项
  • 适用于：博客文章、产品列表、新闻条目等需要多个实例的内容
  • API 特点：
    • 提供获取列表的端点 (GET /api/collection-name)
    • 提供获取单个项的端点 (GET /api/collection-name/:id)
  • 示例：
    • 新闻文章（可以有多个新闻）
    • 产品目录（可以有多个产品）
    • 用户评论（可以有多个评论）

Single Types (单一类型)

  • 只允许一个条目：整个系统只能有一个该类型的实例

  • 适用于：主页内容、公司信息、全局设置等唯一性内容

  • API 特点：

    • 只提供获取单个项的端点 (GET /api/single-type-name)
    • 不需要指定ID

  • 示例：

    • 网站首页内容（只有一个首页）
    • 公司介绍（只有一个公司介绍）
    • 全局配置（如SEO设置）

    如何选择？

    • 如果需要创建多个相似内容项 → 使用 Collection Types
    • 如果只需要一个全局实例 → 使用 Single Types

MockMethod 参数说明

  • url (string): 请求的 URL 路径。

  • method (string): 请求的方法，如 get、post、put、delete 等。

  • response (function | object): 请求的响应，可以是一个对象，也可以是一个函数，用于动态生成响应数据。

    ​ body: 请求体数据（对于 POST、PUT 请求）。
    ​ query: 查询参数（对于 GET 请求）。

    headers: 请求头信息。

    ​ params: 动态路由参数（例如 /api/user/:id 中的 :id）。
    ​ url: 请求的完整 URL。
    ​ method: 请求的方法（例如 GET、POST 等）。
